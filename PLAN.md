# PLAN — Facturo

Идея, границы продукта и фазы реализации. Технические правила — в `CLAUDE.md`.

Документ один и тот же в обоих репозиториях (`facturo`, `facturo-server`), чтобы
любой из них был самодостаточен. Где фаза касается только одной стороны, это
указано явно.

---

## 1. Что мы делаем и почему сейчас

С **1 октября 2026** электронная счёт-фактура становится обязательной для сделок
B2B между плательщиками НДС Молдовы. Государство даёт систему `e-Factura` (СФС) и
API к ней, но не даёт удобного инструмента для компании, у которой нет
бухгалтерской программы.

Боль, за которую платят, — не штраф, а потеря денег: счёт, выставленный вне
системы там, где она обязательна, **не даёт права на вычет НДС**. Всплывает это
при сверке через месяцы, когда исправлять поздно.

**Facturo** — выставление и приём электронных счетов для малого и среднего
бизнеса: три клика вместо госпортала, импорт контрагентов из Excel, понятное
объяснение ошибки вместо кода API.

### Клиент

Компании-плательщики НДС **без 1С** или с 1С, но неудобной: торговля и опт,
услуги B2B (строительство, IT-подряд, консалтинг, логистика), небольшое
производство. Решение о покупке принимает директор или главный бухгалтер.

### Конкуренция

| Кто | Чем закрывает | Чем не закрывает |
|---|---|---|
| Госпортал СФС | Бесплатно, официально | Интерфейс уровня госуслуг, нет импорта, нет объяснений ошибок |
| 1С с интеграцией | Тех, у кого 1С уже стоит | Тех, у кого её нет, — а это наша аудитория |
| Индивидуальные интеграции | Крупных (Orange, Moldcell) | МСП: слишком дорого |
| **Коммерческий продукт для МСП** | — | **Ниша пуста** |

В Румынии под аналогичный мандат выросло несколько прибыльных SaaS
(`factureaza.ro`, FGO, `facturis-online`). Модель проверена рядом. Румынские
игроки не зайдут автоматически: другой API (СФС, а не ANAF), другой закон, другие
реквизиты.

### Честно о сроке

Мандат наступает **1 октября 2026**. Полноценный продукт к этой дате не
успевает, и притворяться иначе — врать самому себе. Расчёт другой: пик спроса
приходится **не на день дедлайна, а на две-четыре недели после него**, когда
компании, не подготовившиеся заранее, начинают искать решение срочно. Поэтому
план целится в **платный запуск во второй половине октября**, а до дедлайна
выводит в закрытую бету рабочий поток «выставить и отправить».

Окно закрывается примерно через 2–3 месяца после дедлайна, когда рынок будет
поделён. Выигрывает тот, кто проще и быстрее, а не тот, у кого больше функций.

## 2. Границы MVP

### Входит

1. Выставление счёта в три клика и отправка через API e-Factura.
2. Импорт контрагентов и позиций из Excel — база заводится за один вечер.
3. Входящие счета: приём, просмотр, акцепт или отклонение.
4. Статусы (отправлено / доставлено / принято / отклонено) с человеческим
   объяснением ошибки вместо кода API.
5. Мобильная версия: счёт выставляется с телефона.
6. Подписка с оплатой картой через maib e-commerce.

### Не входит — и это решение, а не недоделка

Полноценный бухучёт, склад, зарплата, расчёт налогов, банковская выписка,
интеграция с 1С, кассовые чеки. Любой из этих пунктов превращает шестинедельный
запуск в годовой проект. К ним можно вернуться, когда будет полсотни платящих
компаний и они сами скажут, чего не хватает.

### Мультиюрисдикционность с первого дня

Румыния — тот же язык, те же правила ЕС, рынок примерно в восемь раз больше.
Поэтому **ro/ru закладываются с первого коммита**, деньги и адреса не
захардкожены под Молдову, а интеграция с налоговой спрятана за интерфейсом
`EfacturaProvider`. Переход на ANAF — это новый класс, а не переписывание.

## 3. Монетизация

| Тариф | Цена, лей/мес | Исходящих документов | Пользователей |
|---|---|---|---|
| FREE | 0 | 10 | 1 |
| STARTER | 249 | 100 | 3 |
| BUSINESS | 599 | без лимита | без лимита |

Бесплатный тариф существует, чтобы контрагенты компании попали в систему до
первого счёта за подписку. Десять документов — это примерно месяц у самых мелких
и очевидно мало у целевых.

Цены живут в одном месте — `src/modules/billing/model/plans.ts` на сервере, — и
оттуда же читаются страницей тарифов и проверкой квоты. Цена не может разойтись
сама с собой.

Оплата — **maib e-commerce** на бизнес-счёт. Абонентская модель: разовый платёж
за период, с сохранением карты (`billerId`) для продления. Номер карты не
хранится нигде и никогда — только токен от банка.

## 4. Архитектура в двух словах

```
facturo            Next.js 16, App Router, FSD, RTK Query   → Vercel
facturo-server     NestJS 12, Prisma 7, PostgreSQL          → Docker на VPS
                                     │
                   ┌─────────────────┴─────────────────┐
                   │                                   │
         EfacturaProvider                      PaymentProvider
         ├ SandboxEfacturaProvider             ├ SandboxPaymentProvider
         └ SfsEfacturaProvider                 └ MaibPaymentProvider
```

Связывает репозитории **только HTTP API**. Типы клиента генерируются из
OpenAPI-документа сервера (`npm run openapi:export` → `npm run api:generate`), а
не копируются руками и не импортируются из серверного кода.

Две границы с внешним миром спрятаны за интерфейсами. Смысл не в красоте: без них
разработка и CI требовали бы сертификата подписи, договора с СФС и мерчант-аккаунта
банка. С ними весь продукт разрабатывается и тестируется офлайн, а когда реквизиты
появятся, меняется ровно один файл на каждую границу.

## 5. Фазы

Даты — от 12 сентября 2026. Каждая фаза заканчивается тем, что можно показать
живому человеку, а не «готово на бэкенде».

### Фаза 1 — Ядро домена · 16–22 сентября

**Сервер.** Auth целиком по чеклисту безопасности: регистрация, вход, ротация
refresh, выход, смена пароля, аудит каждого события. Модули `companies`,
`counterparties`, `products` — CRUD с фильтрацией по `companyId`. Выдача номера
счёта из `NumberSeries` в той же транзакции, что и создание документа. Импорт
Excel: разбор, построчная валидация, отчёт об ошибках с номерами строк.

**Клиент.** Вход и регистрация, оболочка рабочего пространства, справочники,
экран импорта. Генерация API-слоя из OpenAPI вместо ручных запросов.

**Готово, когда:** можно зарегистрироваться, загрузить список контрагентов из
Excel и увидеть его в интерфейсе на обоих языках.

### Фаза 2 — Исходящие e-Factura · 22 сентября – 3 октября

Самая рискованная фаза, потому что единственная зависящая от внешней стороны.

**До кода:** получить договор об интеграции с СФС и действующий «Ghid de
integrare — API» из раздела Help системы e-Factura, плюс квалифицированный
сертификат подписи. Без этих двух вещей `SfsEfacturaProvider` писать нельзя:
документ, собранный по догадке, отклонит валидатор, и узнает об этом клиент, а не
мы.

**Сервер.** Сборка XML документа. Реализация `SfsEfacturaProvider`. Очередь
отправки с повтором и экспоненциальной задержкой, каждая попытка — строка в
`EfacturaSubmission` с сохранённым запросом и ответом. Опрос статусов. Наполнение
каталога ошибок реальными кодами по мере того, как тестовая среда СФС их выдаёт,
— не выдумывая заранее.

**Клиент.** Форма счёта, оптимизированная под телефон: контрагент, позиции,
итоги, отправка. Экран статуса с объяснением и кнопкой следующего шага.

**Готово, когда:** реальный счёт уходит в тестовую среду СФС и возвращается со
статусом. Затем — закрытая бета на 3–5 пилотных компаний.

### Фаза 3 — Входящие · 3–10 октября

Приём документов от поставщиков, список, просмотр, акцепт и отклонение с
причиной. Эта половина продукта делает Facturo местом, где живут все документы
компании, а не только исходящие.

Здесь же появляется стык с нишей №2 из PLAYBOOK: входящие в машиночитаемом виде
— это готовый поток для бухгалтера.

### Фаза 4 — Оплата · 10–17 октября

**Сервер.** `MaibPaymentProvider`: токен, регистрация платежа, callback с
проверкой подписи SHA-256 в постоянном времени. Жизненный цикл подписки,
проверка квоты перед выставлением документа, продление сохранённой картой.

**Клиент.** Страница тарифов, оплата, страница подписки, предупреждение при
подходе к лимиту.

**Готово, когда:** компания платит картой и лимит поднимается.

### Фаза 5 — Публичная часть и право · 17–24 октября

Лендинг с ценами и FAQ, совпадающим с разметкой `FAQPage`. Полный кластер
hreflang (`ro`, `ru`, `x-default`), canonical, `sitemap.xml` с alternates,
`robots.txt`, `llms.txt`, OG-картинки 1200×630 под каждый язык.

**Условия использования и Политика конфиденциальности написаны и опубликованы**
на обоих языках — простым языком, а не юридическим. Осталось то, что нельзя
сделать в коде: проверка у молдавского юриста, подстановка реальных реквизитов,
решение о форме ведения деятельности и регистрация товарного знака в AGEPI.
Полный список — в `docs/legal/README.md`, и он закрывается **до первого
платящего клиента**, а не после.

Бэкапы: Supabase Pro (PITR) плюс ночной `pg_dump` в GitHub Actions. Второе —
страховка, а не замена первому.

### Фаза 6 — Платный запуск · с 24 октября

Публичный запуск в окно панического спроса. Каналы: прямой обход бухгалтерских
фирм, группы предпринимателей, поиск по запросам про e-Factura. Метрика первого
месяца — не регистрации, а **число компаний, отправивших второй счёт**: первый
отправляют из любопытства, второй — потому что работает.

## 6. Что может пойти не так

| Риск | Почему это больно | Что делаем |
|---|---|---|
| Договор с СФС и сертификат затягиваются | Фаза 2 стоит, а она центральная | Запросить в первый день фазы 1, не фазы 2. Весь остальной продукт разрабатывается на sandbox-провайдере и от этого не зависит |
| API СФС нестабилен или меняется | Документы не уходят, клиент видит ошибку | Очередь с повтором, каждая попытка сохранена целиком, статус «в очереди» вместо «ошибка» на временных сбоях |
| Вендоры бухгалтерского ПО двинутся в ту же нишу | Они больше и у них есть клиентская база | Выигрывает простота: три клика и импорт из Excel против настройки модуля. Не пытаться догнать по функциям |
| Окно закрывается раньше, чем мы запустимся | Рынок поделён | Бета до дедлайна, платный запуск сразу после. Не откладывать ради полноты |
| Мерчант-аккаунт maib не успевает | Нечем принимать деньги | Подать заявку на e-commerce на бизнес-счёт в фазе 1. До этого — sandbox-провайдер, поток оплаты разрабатывается без банка |

## 7. Definition of Done

Задача готова, только когда верно всё:

- [ ] `typecheck` без ошибок
- [ ] `lint` без ошибок и предупреждений, `lint:fsd` чистый (клиент)
- [ ] `build` проходит
- [ ] тесты зелёные, на новую логику добавлены новые
- [ ] нет `any`, нет закомментированного кода, нет отладочных `console.log`
- [ ] UI проверен вживую в браузере, а не только «код выглядит правильно»
- [ ] мобильная вёрстка проверена на ширине 400px
- [ ] оба языка (ro/ru) заполнены, диакритика корректна (ă â î ș ț)
- [ ] секреты не попали в коммит
- [ ] коммит объясняет **почему**, а не пересказывает диф
