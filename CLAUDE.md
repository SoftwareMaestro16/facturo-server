# CLAUDE.md — facturo-server

Технические правила бэкенда Facturo. Идея и фазы — в `PLAN.md`.

Эти правила одинаково обязательны для человека и для ИИ-ассистента. Если правило
мешает — меняем правило в этом файле, а не обходим его в коде.

---

## Команды

```bash
npm run start:dev       # разработка с перезапуском
npm run verify          # lint → typecheck → test → build, то же, что в CI
npm run test            # юнит-тесты (только model/ и utils/)
npm run test:e2e        # e2e, нужна живая БД
npm run prisma:migrate  # новая миграция
npm run openapi:export  # openapi.json, из него клиент генерирует свой API-слой
```

Перед коммитом — `npm run verify`. CI делает ровно это же, поэтому красный CI
после зелёного `verify` означает, что что-то не воспроизводится локально, и это
отдельная проблема.

## Стек

| Слой | Технология | Зачем именно она |
|---|---|---|
| Каркас | NestJS 12 | модули, DI, guards, filters |
| Язык | TypeScript 6.0, strict | без `any` |
| ORM | Prisma 7 + `@prisma/adapter-pg` | миграции, типы из схемы |
| БД | PostgreSQL (Supabase, Session pooler) | см. раздел про БД |
| Авторизация | JWT в httpOnly cookie + argon2 | см. чеклист безопасности |
| Валидация | class-validator + ValidationPipe | whitelist, forbidNonWhitelisted |
| Rate-limit | `express-rate-limit` | `@nestjs/throttler` не поддерживает Nest 12 |
| Здоровье | `@nestjs/terminus` | `/health` с реальной проверкой БД |
| Мониторинг | `@sentry/node` | `@sentry/nestjs` не поддерживает Nest 12 |
| Тесты | Vitest | быстрые юнит-тесты чистых моделей |
| Контракт | `@nestjs/swagger` | OpenAPI — единственный источник типов для клиента |

Версии в `package.json` закреплены не случайно. TypeScript зафиксирован на
`~6.0.3`, потому что это единственный диапазон, который одновременно
устраивает `@nestjs/schematics@12` (требует `>=6.0.0`) и `typescript-eslint@8`
(требует `<6.1.0`). Прежде чем поднимать — проверить оба.

## Архитектура

```
src/
├── modules/
│   └── <domain>/            auth, companies, counterparties, products,
│       ├── dto/             invoices, efactura, billing, imports, health
│       ├── model/           чистая логика без Nest и Prisma
│       ├── providers/       границы с внешними системами (там, где они есть)
│       ├── <domain>.controller.ts
│       ├── <domain>.service.ts
│       └── <domain>.module.ts
├── common/
│   ├── decorators/          @Public, @Roles, @CurrentUser
│   ├── filters/             обработка ошибок
│   ├── guards/              JwtAuthGuard, RolesGuard
│   ├── interceptors/        сериализация Decimal
│   ├── prisma/              PrismaService, PrismaModule
│   ├── types/               AuthenticatedUser
│   └── utils/               деньги, телефон, IDNO
├── config/                  конфигурация из env с валидацией
├── instrument.ts            инициализация Sentry, импорт первой строкой main.ts
└── main.ts
```

### Правила слоёв

- **Контроллер** — только HTTP: маршруты, коды ответов, куки. Логики нет.
- **Сервис** — бизнес-логика и работа с Prisma.
- **`model/`** — чистые функции без Nest и без Prisma. Именно их покрывают
  юнит-тестами. Запрет на импорт `@nestjs/*` и `@prisma/*` в `model/` проверяет
  линтер: см. `eslint.config.mjs`.
- **`providers/`** — граница с внешней системой: интерфейс плюс минимум две
  реализации (sandbox и настоящая). Какая подключена, решает фабрика в модуле,
  читающая env. Больше ни один файл про это не знает.
- **Guard** — авторизация, а не бизнес-правила.

### Почему `model/` отделён

Арифметика счёта и правила смены статуса — это то, что ломается тихо и всплывает
у налоговой. Они должны тестироваться за миллисекунды, без базы, без DI и без
подъёма приложения. Как только в такой файл попадает `@Injectable`, тест
перестаёт быть дешёвым и его перестают писать.

Enum-ы Prisma в `model/` не импортируются — соответствующие union-типы
объявляются на месте. Компилятор проверит совместимость на границе сервиса.

## Правила написания кода

### SOLID — что реально применяем

- **SRP** — главный. Если в описании функции появляется «и», её надо разделить.
  Сервис на 600 строк — это три сервиса.
- **DIP** — там, где есть варианты реализации: `EfacturaProvider`,
  `PaymentProvider`. Не везде подряд.
- **OCP/LSP/ISP** — не изобретать ради принципа. В продукте такого размера
  преждевременная абстракция вреднее дублирования.

### Дополняющее

- **DRY** — но не раньше третьего повторения.
- **KISS** — самое простое решение, которое работает.
- **YAGNI** — не писать код «на будущее». Фича-флаги и слои совместимости для
  гипотетических сценариев запрещены.

### TypeScript

- **`any` запрещён.** Полностью. Неизвестный тип — `unknown` и сужение через
  проверки.
- `strict: true` всегда.
- `@ts-ignore` запрещён; `@ts-expect-error` — только с объяснением рядом.
- Правила линтера не отключаются комментарием без причины в том же комментарии.

### Именование

- Файлы `kebab-case.ts`, классы и компоненты внутри — `PascalCase`.
- Булевы: `isLoading`, `hasSession`, `canEdit`.
- Никаких сокращений: `invoice`, а не `inv`.
- Английский в коде. Русский и румынский — только в i18n и в каталоге ошибок.

### Комментарии

Комментарий объясняет **почему**, а не **что**.

```ts
// плохо — пересказ кода
// увеличиваем счётчик попыток на единицу
const attempts = user.failedLoginAttempts + 1;

// хорошо — объясняет неочевидное решение
// Блокируем на время, а не навсегда: директор, промахнувшийся мимо клавиш на
// телефоне, не должен остаться без выставления счетов в день дедлайна.
```

`///` — описание модуля или публичной функции. `//` — пояснение строки.

### Размеры

Функция до ~40 строк, файл до ~300. Это ориентиры; превышение вдвое требует
обоснования. Линтер предупреждает, но не блокирует.

### Обработка ошибок

- Пустой `catch {}` без комментария, почему это безопасно, запрещён.
- Не защищаться от невозможных состояний. Валидировать на границах: вход
  пользователя, ответ внешнего API.
- 5xx уходят в Sentry, 4xx — нет, это ожидаемый трафик.
- Ответ наружу всегда содержит стабильный `code`, который клиент переводит.
  Текст ошибки от драйвера или стек наружу не уходят никогда.

### Запрещено

- `any`, `@ts-ignore` без объяснения
- хардкод URL и секретов — только через `config`
- логика в контроллере
- импорт `@nestjs/*` или `@prisma/*` в `model/`
- запрос без фильтра по `companyId`
- `Float` для денег
- коммит в `main` без прохождения CI

## База данных

### Подключение

Строка **Session pooler**, порт 5432:

```
postgresql://postgres.[ref]:[password]@aws-0-[region].pooler.supabase.com:5432/postgres
```

- **Direct connection** (`db.[ref].supabase.co`) отдаёт только IPv6, если не
  платить за IPv4-аддон. Большинство VPS и раннеры GitHub Actions туда не
  достучатся.
- **Transaction pooler** (6543) не поддерживает prepared statements и рассчитан
  на serverless с тысячами короткоживущих подключений. У нас один долгоживущий
  процесс с одним пулом.

В Prisma 7 строка подключения **не живёт в `schema.prisma`**. CLI берёт её из
`prisma.config.ts`, приложение — из `PrismaService`, который передаёт её в
pg-адаптер.

### Миграции

- Только через `prisma migrate`. Руками в БД не лезть никогда.
- При старте контейнера: `prisma migrate deploy` (см. `Dockerfile`).
- Имя миграции описывает смысл: `invoice_number_series`, а не `update1`.

### Обязательные правила схемы

- **Мультитенантность.** Каждая бизнес-таблица несёт `companyId`, и **каждый**
  запрос фильтруется по нему. Это не опция — это то, что не даёт одной фирме
  увидеть документы другой.
- **Деньги — только `Decimal`.** `Decimal(12, 2)` для сумм, `Decimal(12, 3)` для
  количества, `Decimal(5, 2)` для ставки НДС. `Float` не встречается нигде.
- **Реквизиты контрагента копируются в документ** при выставлении. Правка
  справочника не должна переписывать уже отправленный документ.
- **Индексы** на то, по чему реально фильтруют: `(companyId, direction, status,
  issueDate)`.
- **Каскады описаны явно**: `onDelete: Cascade` или `SetNull`, не по умолчанию.

### Бэкапы

Бесплатный тариф Supabase не бэкапит автоматически. До первого платящего клиента
— Supabase Pro (ежедневные бэкапы и PITR) плюс ночной `pg_dump` в GitHub Actions
(`.github/workflows/db-backup.yml`). Второе — страховка, а не замена первому.

## Безопасность: чеклист

### Аутентификация

- Пароли — **argon2**. Никогда MD5, SHA или bcrypt без соли.
- Access-токен 15 минут, refresh 30 дней, оба в `httpOnly` cookie с
  `SameSite=Lax` и `Secure` в проде.
- Refresh хранится в БД как SHA-256 хеш. Украденная копия таблицы сессий
  бесполезна.
- **Ротация refresh:** при обновлении старый ревокается. Повторное использование
  ревокнутого токена означает утечку — отзывается вся цепочка.
- Смена пароля отзывает все сессии пользователя.

### Защита от подбора

- Rate-limit: общий на `/api`, жёсткий на `/api/auth/login` и `/api/auth/register`.
- Блокировка аккаунта после 5 неудач на 15 минут — временная, не вечная.
- **Один и тот же ответ** на неизвестный email, неверный пароль и
  заблокированный аккаунт. Иначе перебором выясняется, кто зарегистрирован.

### Пароли

Минимум 8 символов; запрещён пароль, равный телефону аккаунта в любой записи;
запрещён новый пароль, равный текущему. Правила живут в
`modules/auth/model/password-policy.ts` и покрыты тестами.

### Доступ к данным

- Цепочка `JwtAuthGuard` → `RolesGuard`. Аутентификация включена по умолчанию,
  `@Public()` — явное исключение.
- Каждый запрос ограничен `companyId` пользователя.
- `ValidationPipe` с `whitelist: true`, `forbidNonWhitelisted: true`,
  `enableImplicitConversion: false`. Неизвестные поля отклоняются, а не
  игнорируются молча.

### Секреты

- Секреты **никогда** не в git. Только `.env` (в `.gitignore`) и переменные
  окружения деплоя.
- В `.env.example` — плейсхолдеры вида `change_me_*`.
- Приложение **падает при старте**, если в проде секрет содержит `change_me`,
  короче 32 символов, в CORS стоит wildcard или подключён sandbox-провайдер
  e-Factura. Это дешевле, чем обнаружить через полгода токены, подписанные
  публично известным ключом.

### Транспорт

- `helmet()` включён; CSP отключён, потому что API отдаёт чистый JSON.
- CORS — белый список origin из env, никаких wildcard с `credentials: true`.
- `TRUST_PROXY=true` за nginx, иначе rate-limit видит один IP на всех.

### Аудит

Таблица `AuditEvent`: вход удачный и неудачный, блокировка, регистрация, смена
пароля, ротация и отзыв сессии, отправка документа, платёж. Запись
fire-and-forget — сбой аудита не должен блокировать вход.

## Эксплуатация

- **`/api/health`** проверяет реальное соединение с БД, а не «процесс жив».
  Подключить к аптайм-монитору.
- **Sentry** опционален через env: без DSN приложение работает идентично.
- **CI обязателен:** format → lint → typecheck → migrate → test → e2e → build.
  Ничего не пропускается при мерже.
- **Компрессия** ответов от 1 КБ.
- Логи не содержат паролей, токенов и тела запросов авторизации.

## Грабли, на которые уже наступили

Каждая стоила времени. Не повторять.

| Проблема | Симптом | Решение |
|---|---|---|
| `@nestjs/throttler` не поддерживает Nest 12 | `ERESOLVE` при установке | Rate-limit как обычный Express-middleware, `src/common/rate-limit.ts` |
| `@sentry/nestjs` не поддерживает Nest 12 | Конфликт peer-зависимостей | `@sentry/node` плюс свой exception filter |
| `@nestjs/schematics@12` требует TS ≥ 6, `typescript-eslint@8` требует < 6.1 | Установка не резолвится | TypeScript зафиксирован на `~6.0.3` |
| Prisma 7 убрала `url` из `schema.prisma` | `P1012` при `prisma generate` | Строка подключения в `prisma.config.ts`, приложение — через адаптер |
| `baseUrl` в tsconfig устарел в TS 6 | `TS5101` при typecheck | Убрать `baseUrl`, `paths` задавать относительно tsconfig |
| Prisma Decimal режет нули | `25.00` в БД приходит клиенту как `25` | `DecimalSerializerInterceptor`, один раз глобально |
| APP_FILTER применяется в обратном порядке | Catch-all перехватывал всё, 404 превращались в 500 | Общий фильтр регистрировать **раньше** специализированного |
| `HttpStatus` в сравнении с числом | `no-unsafe-enum-comparison` | Сравнивать с обычной константой `SERVER_ERROR = 500` |
| Телефон в разных записях | `069123456` и `+373 69 123 456` считались разными | `normalizePhone` перед любым сравнением или поиском |

## Контракт с клиентом

`npm run openapi:export` пишет `openapi.json`. Клиент генерирует из него весь свой
слой данных (`npm run api:generate` в `facturo`). Из этого следуют два правила:

1. **Каждый публичный эндпоинт описан** декораторами Swagger, включая формы
   ответа и коды ошибок. Неописанный эндпоинт для клиента не существует.
2. **Ломающее изменение API — это ломающее изменение контракта.** Переименование
   поля без переходного периода ломает собранный клиент, а не выдаёт ошибку
   компиляции.

Типы бэкенда в клиент напрямую не тянутся: связь только через HTTP и
сгенерированный контракт.
